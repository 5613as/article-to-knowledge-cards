# Make Knowledge Cards（知识卡片生成）

## Overview

把用户粘贴的文章正文，或指定的本地 Markdown / TXT 文件，提炼成 5～8 张知识卡片。
每张卡片只讲一个知识点，包含四要素：标题、核心知识、简明解释、例子或自测问题。

目标是产出"能直接拿去复习"的卡片，而不是全文摘要或段落缩写。

## 何时使用 / 何时不使用

适用场景：

- 用户粘贴一段文章，要求做成知识卡片 / 学习卡 / 复习卡 / 要点卡
- 用户给出本地 `.md` / `.txt` 文件路径，要求提炼知识点
- 用户要求"帮我梳理 / 记住这篇文章的重点"

不适用（当前不支持，遇到时直接说明并给出替代方案）：

- 网页抓取（只有 URL、需要联网获取的正文）
- PDF、docx、图片等非 `.md` / `.txt` 格式
- 导出 Anki（apkg）等记忆软件格式
- 任何图形界面

## 输入处理

- 粘贴正文：直接作为素材使用。
- 本地文件：用 Read 工具读取 `*.md` / `*.txt`。若路径指向 PDF 或其他格式，说明暂不支持，请用户提供正文或转为 `.md` / `.txt`。
- 无输入：请用户粘贴文章或给出文件路径，**不要**自行编造素材或凭主题自由发挥。
- 材料很长时，完整读取后再提炼，不要只取开头。

## 工作流程

### 1. 通读材料

完整读取输入，把握主题、结构与作者意图。

### 2. 抽取候选知识点

列出材料中所有"能独立成立且重要"的知识点。判断标准：

- 它是否是一个可以被单独记住、单独复述的概念、事实、方法、结论或因果关系？
- 删掉它，读者是否会损失重要信息？

### 3. 去重与合并

- 反复出现、互为表里的点，合并成一张卡。
- 同义表述、以及"论点 + 用于说明它的例子"这类重复，只保留一份。
- 若一个知识点内部包含多个彼此独立的小点，拆成多张卡。

### 4. 选卡（关键约束）

- 目标 5～8 张，按重要性排序取前 N 张。
- **宁少勿凑**：材料能支撑几个就写几张。若只有 3～4 个够格的知识点，就输出 3～4 张，并说明"原文信息不足以支撑更多卡片"。
- 若超过 8 个同样重要，取最重要的 8 张，并可用一句话提示还有若干次要点未展开。

### 5. 写每张卡

四要素的具体要求：

- **标题**：直接点出这张卡讲什么。中文不超过 15 个字；英文不超过 8 个词。
- **核心知识**：用一句话给出结论或事实（是什么 / 为什么 / 怎么做），避免含糊措辞。
- **简明解释**：2～4 句，补充背景、条件或机制以帮助理解；不要写成整段。
- **例子或自测问题**：二选一，标签随所选内容变化——只给例子时用 `例子`，只给问题时用 `自测`，两者都给时用 `例子 / 自测`。概念/事实类偏"例子"，原理/流程/方法类偏"自测问题"。

### 6. 自检

输出前逐条核对下方的"自检清单"。

## 卡片模板

一次性输出全部卡片，卡片之间用 `---` 分隔。可在开头加一行来源说明。

**中文材料模板：**

```markdown
> 来源：{文件名或"用户粘贴内容"}｜共 {N} 张卡片

## 卡片 {n}：{标题}

- **核心知识**：{一句话结论}
- **简明解释**：{2–4 句}
- **例子 / 自测**：{一个例子，或一个能引导回忆的问题}
```

**英文材料模板：**

```markdown
> Source: {file name or "pasted text"} | {N} cards

## Card {n}: {Title}

- **Key point**: {one-sentence conclusion}
- **Explanation**: {2–4 sentences}
- **Example** / **Self-check**: {an example, or a recall prompt}
```

## 按文章类型调整

不同类型的材料，提炼的落点不同：

- **说明 / 科普型**：优先抓定义、机制、以及文中的关键数字与结论；数字必须原样保留。
- **叙事型**：不要复述情节，抓"发生的事情 → 得出的教训/原则"，并保留支撑该教训的关键事实。
- **观点 / 论说型**：区分"作者的主张"与"支撑它的理由"，主张各成一卡；论证过程与例子不单独成卡，除非本身是重要论据。
- **流程 / 操作型**：每个关键步骤一卡，多用"自测问题"帮助回忆步骤与顺序。
- **学术摘要 / 综述型**：区分"研究背景与动机"和"论文自身的贡献与范围"；信息量低的背景铺垫句不必单独成卡，优先保留方法、关键结论、覆盖范围与展望。
- **信息稀疏 / 碎片型**：只提炼真正够格的知识点，**宁可少写**，并说明原因。

## 质量红线（必须遵守）

1. **忠于原文**：只输出材料本身包含的信息；不引入外部知识、不做推测、不补充"常识"。
2. **一卡一点**：一张卡只承载一个知识点，不混合主题。
3. **去重**：重复、同义、举例性内容合并，不出现两张讲同一件事的卡。
4. **不凑数**：信息不足时输出更少的卡；不得为凑到 5 张而重复或臆造。
5. **术语一致**：沿用原文的术语与专有名词；原文出现的数字、比例、版本号必须原样保留。
6. **语言一致**：卡片正文、字段标签、来源说明行都随材料语言变化（中文材料 → 中文；英文材料 → 英文），除非用户另行指定。
7. **只给结果**：直接输出卡片，不要输出"我将要……"之类的过程旁白。

## 自检清单（输出前逐条确认）

- [ ] 每张卡只有一个知识点
- [ ] 卡片数在 5～8，或因信息不足而更少且已说明
- [ ] 没有两张卡讲同一件事
- [ ] 所有内容都能在原文中找到依据，无编造
- [ ] 每张卡四要素齐全
- [ ] 数字、术语与原文字面一致
- [ ] 语言（正文 / 字段标签 / 来源行）与材料语言一致

## 示例

输入（节选）：

> 光合作用是植物利用光能，把二氧化碳和水转化成有机物并释放氧气的过程。它主要发生在叶绿体中，分为光反应和暗反应两个阶段。光反应在类囊体膜上进行，产生 ATP 和 NADPH；暗反应在基质中进行，利用前者固定二氧化碳生成糖。

输出：

```markdown
> 来源：用户粘贴内容｜共 3 张卡片

## 卡片 1：光合作用的定义

- **核心知识**：光合作用是植物利用光能，把二氧化碳和水转化为有机物并释放氧气的过程。
- **简明解释**：它是植物制造自身养分的基本途径，同时向环境释放氧气。
- **自测**：合上原文，能否说出光合作用的原料和产物各是什么？

---

## 卡片 2：光合作用的发生场所

- **核心知识**：光合作用主要发生在叶绿体中。
- **简明解释**：叶绿体为光反应和暗反应提供了各自所需的膜结构与酶环境。
- **例子**：叶片呈现绿色，正是因为叶绿体中含叶绿素、能吸收光能。

---

## 卡片 3：光反应与暗反应的分工

- **核心知识**：光合作用分为光反应和暗反应两个阶段。
- **简明解释**：光反应在类囊体膜上进行，产生 ATP 和 NADPH；暗反应在基质中进行，利用 ATP 和 NADPH 固定二氧化碳生成糖。
- **自测**：光反应的产物中，哪种物质直接为暗反应固定二氧化碳提供能量？
```

> 说明：该材料只够支撑 3 个知识点，因此输出 3 张而非硬凑到 5 张——这正是"不凑数"红线的体现。

## 边界与不支持项

- 仅支持：用户粘贴的文本、本地 `.md` / `.txt` 文件。
- 暂不支持：网页抓取、PDF 及其他富文本格式解析、Anki 导出、任何图形界面。
- 遇到不支持的请求时，简短说明并给出可行替代，例如"请把正文粘贴过来，或转存为 `.md` / `.txt` 后告诉我文件路径"。
