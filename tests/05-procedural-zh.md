# 如何写出好的 Git 提交信息

好的提交信息能让未来的你（和同事）快速理解一次改动。

第一步，用"动词 + 结果"的祈使句写标题，例如 "Add rate limit to login API"。标题控制在 50 个字符以内。

第二步，用空行把标题和正文分开。空行是必须的，否则 git log --oneline 会把正文当成标题的一部分。

第三步，在正文里解释"为什么"，而不是"做了什么"。"做了什么"看代码就懂，而"为什么"往往无法从代码中还原。

第四步，一次提交只做一件事。如果一个提交既修 bug 又加功能，就拆成两个提交；这样出问题时可以单独回滚某一个。

最后，用 git commit -v 查看完整 diff 后再写信息；用 git log --oneline 定期检查自己的提交历史，逐步改进。
